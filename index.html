Before you start

Read this bit

You'll do four things in order:

  • Write your site as plain files in a folder
  • Put that folder in a GitHub repository
  • Switch on GitHub Pages so GitHub serves it
  • Point your own domain at GitHub with DNS records

What you need

  • A GitHub account (free)
  • A domain you control — this guide uses a web3 domain, but the same steps work with any domain whose DNS you can edit
  • Ten minutes
Why plain HTML?

Because there's nothing to break. No framework to update, no runtime to patch, no dependency that vanishes from npm. Your site is a folder of files that will still work in ten years — and if you ever want to move it, you drag the folder anywhere.

The five steps

  1. Write your files
  2. Create the repo & upload
  3. Switch on GitHub Pages
  4. Point your domain at it
  5. Verify it works
01

Write your files

5 min

Make a folder called mysite. Inside it, put these three files. This guide is itself built exactly this way. 

mysite/
├── index.html      ← the page itself (required)
├── styles.css      ← optional, but you want it
├── favicon.svg     ← optional, the little tab icon
├── CNAME           ← step 4, your domain, nothing else in it
└── .nojekyll       ← an empty file, so GitHub serves everything as-is

index.html

GitHub Pages serves index.html at the root automatically.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>My site</title>
  <link rel="stylesheet" href="styles.css">
</head>
<body>
  <h1>It works.</h1>
  <p>Served from GitHub Pages.</p>
</body>
</html>

.nojekyll

An empty file with no extension. GitHub runs Pages through Jekyll by default, and Jekyll ignores folders beginning with an underscore. A .nojekyll file switches that off, so any file or folder name you use gets published as-is.

Do this now

Create .nojekyll before your first push. If you forget, you'll spend an afternoon wondering why a file you clearly committed isn't showing up.

02

Create the repo & upload

4 min

Make the repository

  1. Open github.com/new
  2. Type the folder name into the repository name box — this becomes your site's address: username.github.io/<repo>
  3. Choose Public. Pages on a private repo requires a paid plan.
  4. Leave everything else alone and click Create repository

Upload your files

On the empty repo you'll see a quick-upload box. Drag your three files in, or click choose your files. Then scroll down and Commit changes.

If you’re comfortable with git

Drag-and-drop works, but it caps out at 100 files and gives you no history control. Once you’re past the first commit, the command line is faster: 

git init -b main
git add .
git commit -m "Add site"
git branch -M main
git remote add origin https://github.com/yioliop921/stepbystep.git
git push -u origin main
Never paste your token into a remote URL

URLs like https://user:token@github.com/… end up in .git/config and in your shell history in plain text. If you must, push and then immediately reset the remote with git remote set-url origin https://github.com/yioliop921/stepbystep.git.

Watch the name

Uploading myfile.html instead of index.html gets you a 404. GitHub only serves the root automatically for the exact name index.html, lowercase.

03

Switch on GitHub Pages

3 min

Pages is off by default. In your repo, open Settings → Pages.

  1. Source → choose Deploy from a branch
  2. Branch → main, folder / (root)
  3. Click Save

Wait a minute or two, then refresh. GitHub prints the address your site is now live at, in a green box.

Test this URL now

Open username.github.io/<repo>/ before touching DNS. If your site renders here, GitHub is working perfectly and anything that goes wrong later is a DNS problem, not a Pages problem. That distinction saves a lot of time.

04

Point your domain at it

8 min

Two pieces: a file in the repo, and DNS records at your domain provider.

4a — set the custom domain in GitHub

Back in Settings → Pages, scroll to Custom domain, type your domain, and press Save. GitHub will try to verify it and will usually say DNS is not configured yet — that’s expected at this point, because you haven’t added the records in step 4b.

Web3 domains cannot use HTTPS — leave this alone

If your domain is a web3 domain on the Freename alt-root (anything ending in .virtualsociety, .hodl, .nfts, .metaverse and so on), it is HTTP-only. No certificate can be issued for it, so Enforce HTTPS must stay off and your site will be reached over http://.

If you tick it anyway, GitHub will refuse and tell you the certificate doesn’t exist yet. That error is not a glitch — it means the domain genuinely cannot be verified. Visitors will see a browser warning on http://; there is nothing to fix, and nothing you should be doing about it.

What to do instead

Keep the site honest rather than pretending. Serve it over plain HTTP, don’t collect passwords or personal data on it, and don’t embed anything that needs a secure context. A static page with no secrets has nothing to lose here.

4b — add the CNAME file

In your repo, create a file named exactly CNAME containing one line: your domain, nothing else. 

stepbystep.virtualsociety

GitHub reads this file and serves your repo on that domain. Commit it the same way you committed the others.

This file controls your Pages URL

The moment CNAME exists, GitHub redirects username.github.io/<repo>/ to your domain on the server — a real HTTP 301, not JavaScript. If your domain isn't working yet, that redirect sends everyone to a broken page and your Pages URL stops being usable. If that happens, rename the file to CNAME.disabled and GitHub goes back to serving the Pages URL directly.

4b — add the DNS records

At your domain provider, add these. The A record points at GitHub's servers; the CNAME handles www.

typenamevalueTTL
A@185.199.108.153300
CNAMEwwwusername.github.io300

GitHub uses four anycast IPs. One is enough to get going; adding all four makes the site resilient if any single address is ever withdrawn: 

185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153
The two values people get wrong

The A record is a GitHub address — it stays the same for every Pages site on the internet, and is not tied to your account. The www CNAME, though, must be your username's Pages host, not the repository path. username.github.io, never username.github.io/myrepo.

05

Verify it works

2 min

Check the domain resolves to GitHub before you celebrate:

nslookup yourdomain.com

You want to see 185.199.108.153. Then open your domain in a browser.

What you seeWhat it means
Your siteDone. Everything worked.
404 from GitHubDNS is fine, the repo isn't serving. Check the filename is exactly index.html.
Old host, or 502Your domain still points at its previous host. The DNS change hasn't propagated.
Nothing resolvesNameservers are wrong, or the domain isn't delegated yet.
On waiting

DNS changes can take minutes or hours depending on the provider and the record's previous TTL. If the lookup shows the right IP but the page still errors, give it a while and reload. If the lookup shows the wrong IP, waiting won't help — the records aren't set correctly.

!!

When it goes wrong

Keep this

My Pages URL started redirecting to a dead domain

This is the CNAME file doing exactly what it should — GitHub 301-redirects the Pages URL to your custom domain. If that domain isn't serving yet, rename CNAME to CNAME.disabled and commit. The Pages URL comes back immediately. Rename it back when your domain works.

GitHub says “the certificate does not exist yet”

That's Enforce HTTPS being refused. For a web3 domain this is permanent and correct: those domains can't hold a certificate. Leave the box unticked and carry on. Nothing is broken.

A file I committed isn't showing up

You almost certainly didn't create .nojekyll. Jekyll skips any folder starting with an underscore. Add the empty file and commit — no restart needed.

My domain shows the wrong content / a parked page

The domain still resolves to whatever host it pointed at before. Look up the A record. If it isn't 185.199.108.153, the change hasn't been made or hasn't propagated yet.

www and the bare domain behave differently

That's normal for a few minutes. The A record and the CNAME propagate separately. Once both settle they serve the same site, because GitHub treats both hostnames as yours via the CNAME file.

It worked, then broke after I edited something

Check whether you deleted or renamed index.html, or removed .nojekyll. Both are easy to break accidentally and both are one commit away from fixed.
